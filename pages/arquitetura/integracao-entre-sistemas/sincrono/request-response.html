Request-response

Um cliente faz uma requisição e espera a resposta do serviço. É a base da web.

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

O cliente envia uma requisição (método, endereço, cabeçalhos e corpo) e aguarda. O serviço processa e devolve um status (200, 404, 500…) com o resultado. REST organiza isso em torno de recursos (/pedidos/42) e verbos HTTP (GET, POST, PUT, DELETE). Cada requisição é independente: o servidor não precisa lembrar das anteriores (stateless).

Passo a passo

  1. Cliente envia a requisição
  2. Serviço valida, processa e consulta o que precisar
  3. Serviço devolve status + corpo da resposta
  4. Cliente usa o resultado e segue o fluxo

Quando usar

  • Consultas em que o usuário precisa do resultado agora
  • Operações de cadastro e edição (CRUD) entre front-end e back-end
  • Integração padrão entre sistemas, com suporte em qualquer linguagem

Quando evitar

  • Tarefas longas (minutos): a conexão estoura o timeout
  • Cadeias longas de chamadas: a latência soma e uma falha derruba todas
  • Avisar muitos interessados de um mesmo fato

Exemplos

  • App de banco consultando o saldo
  • Front-end de e-commerce buscando a lista de produtos
  • Checkout chamando a API de frete para calcular o preço

Tecnologias

HTTP, REST, OpenAPI, Express, Spring, FastAPI
