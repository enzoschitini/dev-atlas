RPC / gRPC

Você chama um método de outro serviço como se fosse uma função local, com contrato definido antes.

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

O contrato (serviços, métodos e mensagens) é escrito num arquivo .proto. A partir dele são gerados o código do cliente (stub) e do servidor, em qualquer linguagem suportada. As mensagens viajam em Protobuf, um formato binário compacto, sobre HTTP/2, que permite várias chamadas simultâneas na mesma conexão e streaming nos dois sentidos.

Passo a passo

  1. Define o contrato no arquivo .proto
  2. Gera o código de cliente e servidor
  3. Cliente chama o método no stub, como função local
  4. Servidor executa e devolve a resposta tipada

Quando usar

  • Latência e consumo de banda menores que JSON sobre HTTP/1.1
  • Contratos rígidos evitam erros de integração entre equipes
  • Streaming bidirecional nativo

Quando evitar

  • APIs públicas consumidas direto por navegadores (precisa de gRPC-Web)
  • Quando é preciso ler o payload “a olho” para depurar, sem ferramentas
  • Equipes sem processo para versionar o .proto

Exemplos

  • Microsserviços internos de grandes empresas (o gRPC nasceu no Google)
  • Serviço de pedidos chamando o serviço de estoque
  • Apps móveis em que o tamanho do payload importa

Tecnologias

gRPC, Protobuf, Thrift, tRPC
