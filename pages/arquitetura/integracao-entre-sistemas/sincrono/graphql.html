GraphQL

Uma única consulta em que o cliente escolhe exatamente os campos que quer, vindos de vários recursos.

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

O servidor expõe um schema tipado com tudo que existe. O cliente envia uma query descrevendo o formato do que quer receber; o servidor resolve cada campo (muitas vezes chamando outros serviços) e devolve um JSON com exatamente aquela forma. Além de query (ler), há mutation (alterar dados) e subscription (receber atualizações, em geral via WebSocket).

Passo a passo

  1. Cliente escreve a query com os campos desejados
  2. Servidor valida a query contra o schema
  3. Resolvers buscam cada campo nos serviços/bancos
  4. Servidor monta e devolve um único JSON

Quando usar

  • Over-fetching (campo demais) e under-fetching (várias chamadas para uma tela)
  • Telas e clientes diferentes (web, mobile) com necessidades diferentes
  • Evoluir a API sem criar novas versões de endpoints

Quando evitar

  • Consultas muito aninhadas sem limite derrubam o servidor (use limite de profundidade/custo)
  • Problema N+1 se os resolvers não fizerem batching (DataLoader)
  • Cache HTTP simples é mais difícil que em REST

Exemplos

  • Apps que juntam perfil, pedidos e recomendações numa tela
  • API pública do GitHub (v4)
  • Camada BFF agregando vários microsserviços

Tecnologias

Apollo, GraphQL Yoga, Hasura, Relay
