Server-Sent Events

O navegador abre uma conexão HTTP e o servidor vai enviando eventos por ela, só nesse sentido.

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

O cliente faz um GET pedindo text/event-stream e o servidor mantém a resposta aberta, escrevendo eventos em texto conforme acontecem. A API EventSource do navegador reconecta sozinha e usa Last-Event-ID para retomar do ponto em que parou. É mais simples que o WebSocket: é HTTP normal e se dá bem com proxies.

Passo a passo

  1. Cliente abre um GET com Accept: text/event-stream
  2. Servidor mantém a resposta aberta
  3. A cada fato, servidor escreve um evento no fluxo
  4. Se a conexão cair, o navegador reconecta e retoma do último ID

Quando usar

  • Push do servidor para o cliente sem a complexidade do WebSocket
  • Reconexão automática embutida
  • Notificações unidirecionais em escala

Quando evitar

  • Quando o cliente também precisa mandar mensagens frequentes (use WebSocket)
  • Só trafega texto (UTF-8); binário precisa ser codificado
  • Em HTTP/1.1 o navegador limita conexões simultâneas por domínio

Exemplos

  • Placar ao vivo e feed de notícias
  • Barra de progresso de uma tarefa longa (upload, build)
  • Respostas de IA chegando palavra por palavra (muitas APIs de LLM usam SSE)

Tecnologias

EventSource, HTTP/2, Mercure, frameworks web
