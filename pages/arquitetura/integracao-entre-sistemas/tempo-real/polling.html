Polling e long polling

O cliente pergunta de tempos em tempos se há novidade (polling) ou o servidor segura a pergunta até ter algo (long polling).

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

No polling simples o cliente repete a requisição a cada N segundos: é fácil, mas gera muitas respostas vazias e a novidade só chega no próximo ciclo. No long polling o servidor mantém a requisição aberta até haver um dado (ou estourar o timeout); ao responder, o cliente abre outra. Reduz latência e requisições vazias sem nenhuma tecnologia especial.

Passo a passo

  1. Cliente pergunta “tem novidade?”
  2. Polling: o servidor responde na hora (muitas vezes “não”)
  3. Long polling: o servidor segura até ter dado ou timeout
  4. Cliente processa e pergunta de novo

Quando usar

  • Receber atualizações quando só há HTTP simples (firewalls, sistemas legados)
  • Quando o provedor não oferece webhook nem push
  • Atualizações não críticas no tempo

Quando evitar

  • Intervalos curtos com muitos clientes geram carga enorme no servidor
  • Long polling prende conexões: exige servidor assíncrono
  • Dica: use backoff e ETag / If-None-Match para tornar as respostas vazias baratas

Exemplos

  • App conferindo o status de um pagamento Pix a cada poucos segundos
  • Painel de monitoramento que atualiza de 30 em 30 s
  • Chats antigos, antes do WebSocket, usavam long polling

Tecnologias

HTTP puro, timers / cron, ETag, Socket.IO (fallback)
