CQRS

Usa modelos diferentes para escrever (comandos) e para ler (consultas), cada um otimizado para a sua função.

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

Comandos (criar pedido) passam pelas regras de negócio e gravam no modelo de escrita. As mudanças são propagadas (via eventos) para um ou mais modelos de leitura, desnormalizados e prontos para as telas. As consultas só leem. Cada lado escala separadamente. O custo é a consistência eventual: a leitura pode atrasar um instante em relação à escrita.

Passo a passo

  1. Cliente envia um comando à API de escrita
  2. Regras de negócio validam e gravam no banco de escrita
  3. Um evento propaga a mudança ao modelo de leitura
  4. Consultas são atendidas pelo banco de leitura, já pronto

Quando usar

  • Leituras rápidas com modelos sob medida
  • Escalar leitura e escrita de forma independente
  • Regras complexas de escrita sem poluir as consultas

Quando evitar

  • Aplicações CRUD simples
  • Equipes sem maturidade para lidar com consistência eventual
  • O usuário salva e não vê a mudança na hora: trate isso na interface

Exemplos

  • E-commerce: escrita no banco relacional, catálogo lido do Elasticsearch
  • Dashboards e extratos bancários
  • Sistemas com muito mais leitura que escrita

Tecnologias

MediatR, Axon, Kafka + Elasticsearch, Redis, MongoDB
