API Gateway

Um ponto de entrada que recebe todas as requisições externas e as encaminha ao serviço certo.

Simulação

Mexa nos controles e aperte os botões para ver o padrão funcionando, inclusive quando algo dá errado.

Como funciona

Os clientes falam só com o gateway, que cuida das preocupações transversais: autenticação, limite de requisições (rate limiting), roteamento, cache, logs e até agregação de respostas. Os serviços internos ficam escondidos e podem mudar sem afetar os clientes. Uma variante é o BFF (Backend for Frontend): um gateway por tipo de cliente, como web e mobile.

Passo a passo

  1. O cliente chama o gateway
  2. O gateway autentica e aplica os limites
  3. Roteia para o serviço interno correto
  4. Devolve a resposta (às vezes agregando várias)

Quando usar

  • Segurança e políticas aplicadas em um só lugar
  • Clientes simples, sem conhecer a topologia interna
  • Controle de tráfego e observabilidade na borda

Quando evitar

  • Vira gargalo e ponto único de falha se mal dimensionado
  • Não coloque lógica de negócio nele
  • Adiciona um salto na rede (latência)

Exemplos

  • Apps móveis acessando dezenas de microsserviços por uma só URL
  • APIs públicas com chaves de acesso e planos de uso
  • Migração gradual de monólito para microsserviços

Tecnologias

Kong, NGINX, AWS API Gateway, Apigee, Traefik, Envoy
