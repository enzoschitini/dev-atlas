Overview

Os padrões de comunicação entre sistemas, do pedido-e-resposta ao streaming, em seis grupos.

O que é integração entre sistemas

As formas de dois ou mais sistemas trocarem dados e se coordenarem. Cada forma tem um custo: quem espera quem, o que acontece quando um lado cai, quanto um sistema fica preso ao outro. Escolher bem é escolher o custo que o caso aguenta.

São 22 padrões em 6 grupos. Cada página traz uma simulação interativa do padrão (com falhas, picos e reentregas), como ele funciona, o passo a passo, quando usar, quando evitar, exemplos e tecnologias.

Os padrões

1. Síncrono

Você pergunta e espera a resposta.

  • Request-response — responde agora
  • RPC / gRPC — chama a função do outro lado
  • GraphQL — peça só o que precisa

2. Assíncrono

Você manda e segue a vida.

  • Fila de mensagens — processa depois
  • Pub/Sub — avisa muitos
  • Webhooks — o serviço liga para você
  • Request-reply assíncrono — pede agora, recebe depois

3. Tempo real e push

A informação chega assim que existe.

  • Polling e long polling — fica perguntando
  • WebSocket — conversa nos dois sentidos
  • Server-Sent Events — o servidor só transmite
  • Streaming de eventos — processa sem parar
  • MQTT — leve para dispositivos

4. Lote e dados

Acumula e processa de uma vez, ou observa o que mudou.

  • Batch — processa em lotes
  • CDC — transforma mudança em evento

5. Coordenação e consistência

Como usar tudo isso sem se perder.

  • Saga — transação em passos, com desfazer
  • Outbox — nunca perca o evento
  • Event sourcing — a história é a verdade
  • CQRS — separa ler de escrever
  • Scatter-gather — pergunta a todos e junta
  • Gossip — a notícia se espalha

6. Infraestrutura de apoio

A base que organiza o tráfego.

  • API Gateway — porta de entrada única
  • Service mesh — rede inteligente entre serviços
